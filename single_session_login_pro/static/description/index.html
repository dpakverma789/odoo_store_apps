BUILT FOR EVERYDAY ADMINISTRATION

More control. Less guesswork.

01 / LOGIN POLICY

Decide which login wins.

Keep Free's latest-login-wins behavior, or reject a new login while an existing session is active. The policy applies after successful MFA; per-user exceptions remain available.

02 / IDLE PROTECTION

End inactivity, not productivity.

Set an idle timeout and warn users before expiry. Stay Logged In records activity; background checks do not. The server enforces expiration even if browser timers stop.

03 / ACTIVE SESSIONS

See who is signed in.

Give administrators one place to review users, login times, last activity, browsers and IP addresses. End an individual session with a confirmation and server-enforced revocation.

04 / CLEAR MESSAGES

Explain why a session ended.

Show understandable reasons for a replaced session, rejected login, idle timeout or administrator termination, so users know what happened and what to do next.

05 / SESSION HISTORY

Keep the context that matters.

Review login and end times, activity, status and end reasons. For administrator revocation, see who ended the session. Completed records remain available in basic session history.

06 / HISTORY RETENTION

Keep history manageable.

Choose how many days to retain completed session records. Automatic cleanup leaves active sessions intact. Set retention to 0 when you want to keep history indefinitely.

A SIMPLE UPGRADE PATH

Start with Free. Add Pro when you need more.

  1. Add both module folders. Place single_session_login and single_session_login_pro in your Odoo addons path.
  2. Install Single Session Login Pro. Odoo installs Free automatically as its dependency. Already using Free? Install Pro on top.
  3. Configure your session policy. Open Session Control → Configuration to set the conflict policy, idle timeout, warning and history retention.

Before you choose

Can I use Free without buying Pro?

Yes. Free works independently and provides the basic single-session restriction. Pro adds the controls shown in the comparison above.

What happens to MFA and users allowed multiple sessions?

The conflict policy waits for successful MFA completion. Allow Multiple Sessions bypasses the single-session conflict policy; Pro's idle controls can still apply.

Who can manage sessions?

The dashboard, history, configuration and session-termination action are restricted to system administrators.
